# Plan: Agri-web-app Business & Architecture Documentation

## Goal
Create business-focused documentation for the Agri-web-app project to prepare for UI/UX feature development. The documentation must bridge the current boilerplate state with the intended agriculture business domain.

## Current State Analysis
- **Project**: Agri-web-app monorepo at `/home/robert/Agri-web-app/`
- **Backend** (`be-agri`): ACK NestJS Boilerplate (generic enterprise auth/RBAC system). Modules: auth, user, role, session, activity-log, api-key, country, email, feature-flag, health, hello, password-history, policy, term-policy. **No agriculture-specific modules yet.**
- **Frontend** (`fe-agri`): Bulletproof React monorepo with 3 apps (Next.js App Router, Next.js Pages Router, React Vite). Features implemented: auth, users, teams, discussions, comments, landing (portfolio-style).
- **Business Domain**: Currently generic boilerplate infrastructure. Project name implies agriculture focus, but no domain-specific business logic exists yet.

## Decisions Required

### 1. Scope of Documentation
Create the following documentation structure:

**In `/home/robert/Agri-web-app/fe-agri/docs/`:**
- `overview/project-overview.md` - High-level business context, intended agriculture domain, current vs target state
- `overview/tech-stack.md` - Consolidated frontend + backend tech stack
- `overview/features.md` - Catalog of currently implemented generic features with UI/UX notes
- `overview/architecture.md` - How the 3 frontend apps relate to each other and the backend

**New directory `/home/robert/Agri-web-app/backend-docs/`:**
- `README.md` - Backend project overview, ACK NestJS boilerplate context
- `api-surface.md` - Catalog of available backend endpoints grouped by module
- `auth-rbac.md` - Authentication, roles, permissions model for UI/UX planning
- `database-schema.md` - Prisma/MongoDB entities relevant to frontend features
- `integration-patterns.md` - How frontend apps consume the backend API

### 2. Business Domain Definition (Critical)
The current codebase is a generic template. The documentation must:
- Explicitly state the intended agriculture business domain (since the project name is Agri-web-app)
- Identify which generic features map to agriculture use cases (e.g., discussions → farm forums, users → farmers/experts, teams → farming cooperatives)
- Flag gaps where agriculture-specific features are missing (crops, fields, weather, irrigation, harvest, soil data, etc.)
- Provide a feature roadmap placeholder for domain-specific modules

### 3. UI/UX Preparation Focus
Each documentation file must include:
- User roles and their capabilities (already in code: USER, ADMIN)
- Page/route inventory per app
- Component inventory per feature module
- Data flow notes for API consumption
- Empty states and loading patterns used in the codebase
